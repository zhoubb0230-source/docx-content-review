### 2026-08-06 按用户五条需求对齐（详见 `requirements-alignment.md`、ADR-021…023）

用户明确的五条需求：错别字 / 语义语病 / 前后描述逻辑 / 前后数据一致 / 特定场景描述范式。
对照后需求 2、3、4 已由 A/B 类与 L 规则覆盖，需求 1 是半成品、需求 5 完全缺位，本轮补齐：

1. **错别字通道转正**（ADR-023）。原状态是断的：description 里承诺了错别字，
   主流程里没有 typo 支线；`scan` 产出裁定 payload、`merge` 准备好读裁定结果，
   中间那步没有 prompt 模板。补 `pass1-typo.md`、接入 SKILL.md 第 4.5 步、
   词表 41 → 210 条、加 `typo_scan.py lint`、默认开启。
   **不做未登录词检测**——需 5 万词级词表，内置的只有 117 词。
2. **新增 P 类范式审查**（ADR-021）。规则外置成 YAML，**加规则不改代码**。
   脚本按 `scope` 确定性定位场景，模型只答「这个要件出现了吗：Y/N/U」，
   U 按齐备处理。永不生成修订，严重度上限 Medium。默认关闭，无规则包时自动跳过。
3. **侧通道的输出隔离**（ADR-022）。`verify_span.py` 加 `--out/--cap`、
   `filter_neverflag.py` 加 `--file`——原先侧通道过闸门会覆盖主通道产物。
4. **修了一个失效的守卫**：交付/临时目录拆分（ADR-016）后，显式指定的临时根
   落在源文档所在目录不再被拒绝。该目录是中间件整棵树的读写位置。
5. 优先级序列调整：「错别字召回率」插到「逻辑检出率」之前（理由见 ADR-023）。

### 2026-08-05 首次真实运行后的修正

用户实跑一轮后反馈了四个问题，均已修复（详见 ADR-016…019）：

1. 中间件与交付物混在一起 → 拆成**交付目录**与**临时目录**两个概念。
   临时目录默认仍跟随工作目录（`<工作目录>/docx-review/`），可用 `--temp-dir` 挪到别处。
2. 交付物混在临时目录里 → **交付物一律写工作目录**，临时目录只剩中间件，
   可用 `workspace.py clean-temp` 整体删除而不影响交付物。
3. 交付物文件名无辨识度 → 统一为 `<原文件名>审查版_<时间戳>.<后缀>`，五个产物共用前缀。
   **随后进一步收窄：只有审查版 docx 是交付物**，报告/xlsx/metrics/术语表照常生成但留在
   `<run>/output/`，随临时目录清理（ADR-020）。
4. 批注里的 `【L06】` 读不懂 → 批注正文改用中文说法，规则号降为末尾的可追溯标记；
   同时修掉两处文案错误（同段落被渲染成"本处与彼处冲突"、非互斥规则误用
   「请确认以哪一处为准」）。

## 未完成 / 待验证

### 0. 首轮真实模型基线（2026-08-06，仅 `sample-basic` 与 `negative-set`）

**这是 prompt 第一次被真实模型跑。** 结论与由此改掉的两处见 ADR-024、025。

| 项 | 结果 |
|---|---|
| 负样本集（34 段合法表达） | 上报 0 条 —— **误报率 0%**（验收线 ≤5%） |
| 正样本集 A 类召回 | 20/23 = **87%**（验收线 ≥80%） |
| 正样本集 B 类召回 | 5/5 = 100% |
| 四道脚本闸门丢弃 | 幻觉 0、长度 0、闸门②降级 0、不改清单 0 —— **一条没丢** |
| 单片截断 | 25 → 20，**砍掉的 5 条恰好是全部 B 类** → 已修（ADR-024） |

**三条 A 类漏报都落在同一处**：需要重写才能改对的句子（「必须对所有出域数据进行。」
补法不唯一；两条一动带两宾的搭配不当只能重构）。这正是 `requirements-alignment.md` §4
提出 B6 的那类情形——**实测数据支持了那个判断**：现有类别体系对
"确实有错、但没有唯一最小修改"的句子没有出口。

**第二轮：事实抽取（`pass1-extract`）在 `logic-injection` 上**

| 项 | 结果 |
|---|---|
| 我的抽取触发的 L 规则 | 26 条 |
| 参考台账（修正前）触发 | 27 条，**其中 L23 靠一条杜撰记录** |
| 参考台账（修正后）触发 | 27 条，全部有出处 |

差异全部指向 fixture 自身的问题，不是抽取质量问题（详见 ADR-026）：

- **L23 此前是假通过**。参考台账里有一条 subject 写「数据层」、锚点却指向
  讲多租户隔离那句的 status；文档里根本没有与该结论矛盾的状态句。
  已给文档补上真实的另一半，并加了「参考台账的每条事实都能在正文中找到出处」
  这道守卫 + 负向对照。
- **L11、L24 参考台账根本没抽到**，因此这两条规则长期没有任何断言覆盖，
  而真实抽取能触发它们。已补进回归的规则断言。
- 我的 L04 出了 2 条候选而参考只有 1 条：同一实体关系在多个段落各记了一次。
  不是误报，但会让评审人看到重复条目——**跨片去重是 Pass 3 的已知薄弱点**，记入未决问题。

**这两份基线的效力边界要说清楚**：跑它的模型能力高于本技能面向的"中等能力模型"，
所以 0% 误报是**上限而非典型值**。它证明的是「prompt 与不改清单本身不诱导误报」，
不能替代中等模型上的实测。A/B 盲测的位置一致率（M2 验收项）也还没测。

### 1. 全部 LLM 侧 prompt 未经真实模型验证 ⚠️ 最重要

`pass1-review.md` 已由上面那轮基线覆盖，**其余六份仍未用真实模型跑过**：

- 范式要件裁定的一致性

`pass1-extract` 已由第二轮覆盖。**剩下最要紧的是 `pass2-verify` 的盲测 A/B 位置一致率**

## 未决问题

- **L29–L32 的误报率没有基线。** SPEC 要求"首轮跑完应人工核对其误报率，再决定是否提升
  其地位"。目前默认 `coverage_rules_to_comment: false`（只进报告），在拿到基线前不要改。
- **XSD 校验是已知缺口**（ADR-007）。若要补齐，需决定是否内置 ECMA-376 schema
  （数 MB + 分发许可问题）。
- **`report.py` 的「术语表覆盖率」一节按 `preferred` 是否出现在全文判定**，
  对有 scope 限定的术语会偏乐观。真实语料上看过再决定要不要按 scope 细化。
- **P 类的误报率没有基线。** 与 L29–L32 同样的处境：`severity_cap: Medium`
  是保守缺省，拿到真实规则包的基线前不要放宽，也不要给 P 类开修订口子。
- **同一实体关系在多个段落各出现一次时，L04 会产出多条候选。** 实测基线里
  「边沿节点/边缘结点」出了 2 条。不是误报，但评审人会看到重复条目。
  跨片、跨段的候选去重是 Pass 3 的已知薄弱点，等真实语料上看过再决定合并策略。
- **范式规则只看单个段落。** "风险表述分散在连续三段里"会被判成缺要件。
  规则该用 `min_chars` 或更严的 `paragraph_regex` 把这类段落排除；
  是否要支持跨段落范式，等真实语料上遇到了再定。

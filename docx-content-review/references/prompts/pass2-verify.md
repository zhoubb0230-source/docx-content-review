# Pass 2 · 二次独立复核 prompt 模板（盲测 A/B）

**这是四道闸门里唯一一道靠模型的闸门，它的设计要点全在"不给锚点"上。**

## 为什么是盲测 A/B

把 `category: A2` 连同原文一起交给模型，等于告诉它"这里有个错，你确认一下"——
这是锚定，确认率会被显著抬高，复核就退化成了橡皮图章。
但反过来问"这段文字是否存在需要修改的问题"又是开放题，中等模型会持续发现新问题。

两难的解法是盲测 A/B：**不告诉模型问题类别，也不告诉它哪一个是原文。**
这同时达成三件事——消除锚定、保持封闭选择题、并且顺带验证了"建议确实优于原文"。

## 调用约束

- **必须实现 A/B 位置随机化**：LLM 在成对比较中的位置偏好是已知问题，
  固定顺序会引入新的系统性偏差。随机种子记入 manifest 以保证可复现。
- 一次调用可批量处理 ≤10 组，降低成本。
- 温度 0。不要在 prompt 中出现类别名、规则号、"错误""问题""修改"之外的任何提示。

## 形式一：有 `suggested_text` 的条目（A 类、L25/L26）

```
以下每组给出两种表述，判断哪一种存在明确的语言错误。

第 1 组
A. {{文本一}}
B. {{文本二}}
上下文（仅供理解，不要评价上下文本身）：{{前后各一段}}

第 2 组
…

对每一组只回答一个词：A / B / 两者都没有 / 两者都有
输出格式：每行 `组号 答案`，例如 `1 A`。不要任何其他文字。
```

判定表（`{{文本一}}` `{{文本二}}` 由程序随机分配为原文与建议）：

| 模型回答 | 结果 | 理由 |
|---|---|---|
| 选中**原文**所在项 | **通过** | 模型独立认出了原文有错，且认为建议更好 |
| 选中**建议**所在项 | 淘汰 | 建议反而更差 |
| 两者都没有 | 淘汰 | 模型认为原文没问题 |
| 两者都有 | 淘汰 | 模型未能区分，视为不可靠 |

## 形式二：无 `suggested_text` 的条目（B 类）

无法做 A/B，退化为封闭单问：

```
下面这段文字中，「{{片段}}」处的{{指代/歧义/结构}}是否会导致读者产生两种以上理解？

上下文：{{前后各一段}}

只回答：YES / NO / UNSURE
```

**UNSURE 一律按 NO 处理**（即淘汰）。这是本技能接受召回损失换取精确率的地方，
不要为了"多留一些"而把 UNSURE 当 YES。

## 触发范围（受 strictness 控制）

| strictness | 启用类别 | 二次复核范围 |
|---|---|---|
| `conservative` | A | 全部 A 类 |
| `balanced`（默认） | A + B | 全部 A + B 类 |
| `thorough` | A + B + C | A + B（**C 类跳过复核，且只进报告**） |

## 结果写回

在 `issues-verified.jsonl` 的原记录上追加：

```json
{"verify":{"result":"pass","method":"blind_ab","position":"A"}}
```

`result` ∈ `pass` / `drop`。`position` 记录原文当时被放在哪一侧，供偏好分析使用
（M2 验收要求：两种排列下的判定一致率 ≥90%，低于此说明模型存在强位置偏好，需换 prompt）。

## 落笔门槛（固定，不可放宽）

只有 **A 类 + 有 suggested_text + 通过分类编辑距离 + 二次复核 pass** 才生成修订。
等价于 `apply_threshold = conservative`。用户要求放宽报告门槛可以照办，
但**落笔门槛不放**。

# 报告模板（`report.py` 的输出骨架）

本文件描述 `report.md` 的固定章节与各节的数据来源，供修改 `report.py` 时对照。
**章节顺序与标题固定**，评审人依赖它定位；增删章节要同步改本文件。

```
---
spec_version / schema_version / skill_version / runid      ← 版本标识（SPEC §10.6）
---

# 内容审查报告：<原文件名>

## 1. 执行摘要
   文档规模（段数/字数/页数，注明页数是估算还是按 app.xml 校准）
   分片数与 token 计量方式（tokenizer 名；估算时注明已按保守系数放大）
   分片完成情况（done/total，failed，skipped）
   问题总数（按严重度分档）
   交付动作（修订/批注/仅报告）
   耗时
   置信策略说明 ← 固定文案，向评审人交代"为什么可以信这份报告"
   被截断/降级项数
   ⚠️ 回写校验未通过时的警示（含具体失败的检查项）
   ⚠️ 源文档 sha256 在运行期间变化的警示

## 2. 必须人工确认项（严重级逻辑冲突）
   按章节排序，每条列出冲突双方的原文、章节路径、页码
   文案不得暗示哪一处是对的——只说"请确认以哪一处为准"

## 3. 分类统计
   按 A/B/C 与 L 规则的计数表，附主要动作

## 4. 按章节明细
   以 heading_path 组织；每章一张表：id / 严重度 / 规则 / 页 / 原文 / 建议或说明

## 5. 术语表覆盖率
   三层各有多少条目；其中多少在文档中实际出现
   文档中未被覆盖的高频术语（按频次降序前 30，供用户补充到权威表）
   待确认概念族（cluster_confirmed=false 的族，明确标注"未确认前不触发任何规则"）

## 6. 本次未覆盖范围
   代码段落 N 处、表格 N 个、超长分片 N 个、未完成分片 N 个，各自原因
   未启用的能力（错别字专项、论证链审查）
   本技能的固有非目标（格式排版、事实核查）

## 7. 参数快照
   strictness / apply_threshold（注明固定不可放宽）
   分片参数 / 术语表来源与条目数 / 运行时间 / 源文档 sha256（注明全程只读）

---
结尾两段固定提示：
  ① 如何用本次自建的术语表让下一轮更准（这是从"无参照物"到"有参照物"的唯一路径）
  ② 如何在 issues.xlsx 标注人工决策并回灌审查记忆（首轮为空是正常状态）
```

## issues.xlsx 列定义

`id | 严重度 | priority_score | 类别 | 规则ID | 章节路径 | 页码 | 原文 | 建议 | 动作 |
复核结果 | 记忆命中 | 人工决策 | 备注`

- 第 1 行是版本标识，第 2 行才是表头，数据从第 3 行开始（`freeze_panes = "A3"`）。
- `priority_score` **完全由脚本计算，仅用于展示排序，不参与任何自动判定**（D2）。
- `人工决策` 是空列，供评审人填 `accept` / `ignore`，再由 `import_decisions.py` 回灌。
- **增列必须递增 `schema_version`**，否则下游工具会静默错列。
